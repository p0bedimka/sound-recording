# Sound Recognition System

Проект прошивки для STM32F412RET6, который принимает PDM-аудио с цифрового микрофона MP34DT05, преобразует его в PCM через аппаратный DFSDM и передаёт аудиопакеты по USART3 с помощью DMA по команде ПК.

Текущий этап — проверка живого аудиотракта и запись звука на ПК. Детектор сирены, DSP-признаки и ML-модель ещё не реализованы.

## Аппаратная конфигурация

| Узел | Подключение / параметры |
|---|---|
| MCU | STM32F412RET6, Cortex-M4F |
| Микрофон | MP34DT05, цифровой PDM |
| PDM clock | PC2 / DFSDM1_CKOUT |
| PDM data | PB1 / DFSDM1_DATIN0 |
| Выбор канала микрофона | L/R подключить к GND |
| Индикатор | PB2 / LED_BLUE |
| UART передача | PB10 / USART3_TX |
| UART приём | PC5 / USART3_RX |

Пины CKOUT и DATIN0 должны соответствовать разводке платы. Для микрофона требуется питание и развязка согласно его документации. Подключите USB-UART TX к PC5, RX к PB10, соедините GND и используйте адаптер, поддерживающий 921600 бод.

## Тактирование и периферия

- HSE задан как 8 МГц; PLL: `M=8`, `N=192`, `P=2`, SYSCLK = 96 МГц.
- AHB = 96 МГц, APB1 = 48 МГц, APB2 = 96 МГц, PLLQ = 4 (48-МГц домен).
- DFSDM использует системную частоту, CKOUT делится на 30: ожидаемая частота PDM clock — 3,2 МГц.
- DFSDM1 Channel 0: внешний вход, SPI rising edge, внутренний clock, offset 0, right bit shift 2.
- DFSDM1 Filter 0: Sinc3, `FOSR=25`, `IOSR=8`, continuous regular conversion, DMA включён. Суммарный коэффициент децимации 200; ожидаемая частота PCM — 16 кГц.
- DMA2 Stream0 (Channel 7): DFSDM → память, circular, 32-битные слова, memory increment, very-high priority.
- USART3: 921600 бод, 8N1, без flow control, двусторонний TX/RX.
- DMA1 Stream3 (Channel 4): память → USART3 TX, normal mode, byte alignment, low priority.
- NVIC: DMA2 Stream0 priority 0, DFSDM1 Filter0 priority 1, DMA1 Stream3 priority 5, USART3 priority 6, SysTick priority 15.
- RTC использует LSE, делители 127/255. При первом запуске календарь устанавливается в 00:00, 1 января, год 00; маркер в RTC backup-регистре предотвращает повторный сброс календаря при последующих запусках с сохранённым backup-доменом.

Значения частот HSE в `.ioc` и `stm32f4xx_hal_conf.h` должны совпадать с фактическим кварцем/генератором на плате. Если HSE не 8 МГц, сначала исправьте PLL и связанные частоты.

## Индикация

Синий `LED_BLUE` на PB2 управляется модулем `../Core`. Паттерны описаны таблицами шагов и таблицей `patterns`; длительности обрабатываются через `HAL_GetTick()`, без `HAL_Delay()` и блокировки аудиопотока.

| Событие (`indicator_event_t`) | Паттерн | Повтор |
|---|---|---|
| `INDICATION_PERIPHERALS_READY` | один импульс 180 мс | нет |
| `INDICATION_DETECTION` | три коротких импульса по 100 мс с паузами по 100 мс | нет |
| `INDICATION_ERROR` | два импульса по 600 мс с паузой 250 мс, затем пауза 800 мс | да |

После успешной инициализации GPIO, DMA, DFSDM1, RTC и USART3 запрашивается `INDICATION_PERIPHERALS_READY`. В `app_run()` функция `indicator_update()` вызывается регулярно; по окончании шаблона LED выключается. События обнаружения и ошибки уже имеют шаблоны, но пока не подключены к логике детектора/восстановления.

Для добавления индикации добавьте значение в `indicator_event_t`, последовательность `indicator_step_t` и запись в `patterns`, затем вызывайте `indicator_request(EVENT)` из прикладного кода. Запрос нового события заменяет текущий паттерн. Вызывайте API из основного контекста, а не из ISR.

## Аудиотракт

```text
MP34DT05 PDM
  → DFSDM1 Channel 0 / Filter 0
  → DMA2 Stream0, circular buffer из 160 × int32_t
  → по команде START main loop обрабатывает две половины по 80 сэмплов в PCM16
  → пакетирование с заголовком, номером последовательности и аппаратным CRC-32
  → DMA1 Stream3
  → USART3_TX (PB10) → ПК
```

При запуске прошивка ожидает команду с ПК. Команды принимаются по USART3_RX с помощью прерывания; запись запускается только по START и останавливается по STOP. DFSDM half-transfer и transfer-complete callbacks отмечают готовность одной из двух половин буфера. Каждая половина содержит 80 аудиосэмплов (5 мс при 16 кГц). Основной цикл копирует значения `raw >> 8` в пакет PCM16 и запускает UART DMA. Буферы UART и DFSDM не разделяются, поэтому DMA UART не удерживает участок circular-буфера после начала передачи.

Передача не блокирует основной цикл ожиданием UART. Если DMA-передача занята, аудиоблок отбрасывается, а пропуск можно обнаружить по номеру пакета. Уже начатый UART DMA-пакет может завершиться после команды STOP. Ошибки UART или DFSDM приводят к `Error_Handler()`.

## Формат UART-аудио

Формат кадров, команд START/STOP, CRC и пример байтов команд описаны в [`Docs/UART_PROTOCOL.md`](Docs/UART_PROTOCOL.md). Поток полностью бинарный: не передавайте по этому UART текстовые диагностические сообщения.

| Параметр | Значение |
|---|---|
| Формат полезной нагрузки | PCM signed 16-bit, little-endian |
| Частота дискретизации | 16000 Гц |
| Каналы | 1 (mono) |
| Длина аудиопакета | 174 байта: 10 байт заголовка + 160 байт PCM + 4 байта CRC32 |
| Длина аудиополезной нагрузки | 80 сэмплов / 160 байт |
| Интервал блока | 5 мс |
| Полезная скорость | 32000 байт/с (256 кбит/с) |
| UART-линия с 8N1 | около 348 кбит/с с учётом заголовка, CRC и старт/стоп-битов |
| Настроенная скорость UART | 921600 бод |

ПК должен сначала отправить корректный кадр START, затем разбирать входящие аудиокадры по sync, длине и CRC. Для остановки отправляется STOP. При извлечении WAV сохраняйте только payload аудиокадров и интерпретируйте его как mono, 16 кГц, signed PCM16 little-endian.

## Счётчики аудиотракта

Счётчики объявлены в `../Core` и обновляются в `../Core`:

- `audio_capture_blocks` — число половин DMA-буфера, принятых как готовые.
- `audio_capture_overruns` — готовый фрагмент был помечен повторно до обработки основным циклом.
- `audio_uart_blocks` — число успешно запущенных UART DMA-передач.
- `audio_uart_drops` — фрагменты, отброшенные при занятом UART DMA.
- `audio_uart_errors` — ошибка запуска или выполнения передачи UART.
- `audio_dfsdm_errors` — ошибки DFSDM.
- `audio_uart_command_errors` — некорректная версия/CRC/длина кадра или переполнение очереди команд.

Счётчики не выводятся в UART, потому что он используется для команд и бинарных аудиопакетов. Их можно смотреть в debugger/watch. Для диагностического вывода используйте отдельный канал либо временно изменённый режим передачи.

## Сборка и запуск

Проект рассчитан на STM32CubeIDE/CubeMX (STM32Cube FW_F4) и CMake-конфигурацию, использующую `arm-none-eabi-gcc`.

Из корня репозитория:

```powershell
cmake --build build --parallel 4
```

Сборка создаёт `build/sound-recognition-system.elf`, `.hex` и `.bin`. После прошивки проверьте, что синий LED коротко мигнул после инициализации, измерьте CKOUT на PC2 (ожидается около 3,2 МГц), затем захватите UART и проверьте длительность/частоту PCM на известном тестовом звуке. Успешная компиляция не заменяет проверку тактирования, микрофона и UART на собранной плате.

## Структура проекта

- `Core/Src/main.c` — HAL startup, системное тактирование и CubeMX-инициализация.
- `Core/Src/stm32f4xx_hal_msp.c` — GPIO alternate functions и DMA MSP-настройки.
- `Core/Src/stm32f4xx_it.c` — IRQ dispatch для DMA и USART.
- `../Core` — парсер команд UART, управление записью, готовность блоков, упаковка аудиокадров и счётчики.
- `../Core` — публичный интерфейс приложения и диагностические счётчики.
- `Docs/UART_PROTOCOL.md` — спецификация UART-команд и аудиокадров для реализации ПК-сервера.
- `../Core`, `../Core` — таблица LED-индикаций и неблокирующее обновление.
- `Core/Inc/stm32f4xx_hal_conf.h` — настройки HAL, включая `HSE_VALUE`.
- `sound-recognition-system.ioc` — конфигурация CubeMX.

## Текущее состояние и дальнейшая работа

Реализованы инициализация тактирования и GPIO, DFSDM PDM→PCM, запуск/остановка записи командами UART, circular DMA-захват, нумерованные CRC-защищённые аудиокадры, базовый учёт потерь/ошибок, RTC backup-маркер и LED-индикация завершения инициализации.

Пока не реализованы: фильтр высоких частот, log-mel/sweep-признаки, gate детектора, обучение/интеграция модели, буферизация событий и автоматическое создание WAV на ПК. Также необходимо подтвердить на конкретной плате номинал HSE, разводку сигналов микрофона и работу USB-UART на выбранной скорости.
