# План реализации ПК‑приложения «UART Audio Recorder» (Qt / C++)

## 0. Что именно делаем (фиксация требований)

| Требование | Реализация |
|---|---|
| Выбор COM‑порта из доступных | `QSerialPortInfo::availablePorts()` + ComboBox + кнопка «Обновить» + автоопрос раз в 1 с |
| Кнопка «Начать запись» активна только после выбора порта | Конечный автомат UI (см. §4) |
| START по протоколу v2 | Бинарный кадр `A5 5A 02 01 …` (14 байт), seq = 0 |
| Кнопка превращается в «Остановить запись» | Toggle‑кнопка, отправка `A5 5A 02 02 …` |
| Каталог записи | `Data/<yyyy-MM-dd_HH-mm-ss>/` |
| Файл 1 — содержимое и нумерация пакетов | `packets.log` (заголовок сессии + запись на каждый кадр: seq, время, длина, CRC, hex‑дамп) |
| Файл 2 — несжатая запись | `recording.wav` (PCM16, mono, 16000 Гц); AIFF — опционально |
| Только два файла в папке | Метаданные/статистика пишутся в шапку и хвост `packets.log`, отдельные файлы не создаём |

Важно: UART полностью бинарный — приложение **не отправляет ничего, кроме кадров START/STOP**, и не ожидает ACK. Подтверждение старта — первый валидный аудиокадр.

## 2. Протокольный слой (самая ответственная часть)

### 2.1 CRC‑32/MPEG‑2
Параметры: poly `0x04C11DB7`, init `0xFFFFFFFF`, RefIn/RefOut = false, XorOut = `0x00000000`.
Покрывается диапазон **version … payload** (sync‑байты исключены), результат сериализуется **little‑endian**.

Ключевое наблюдение: длина покрываемой области всегда кратна 4 (8 + 0 или 8 + 160), поэтому побайтовый алгоритм MSB‑first даёт **тот же результат**, что подача big‑endian 32‑битных слов в аппаратный CRC STM32. Реализуем табличный побайтовый вариант (таблица 256 × uint32, генерация constexpr).

```cpp
uint32_t crc32_mpeg2(const uint8_t* data, size_t len); // init 0xFFFFFFFF, без финального XOR
```

**Тест‑векторы из спецификации (обязательный unit‑test):**
* `02 01 00 00 00 00 00 00` → CRC `0x91106ADC` → в проводе `DC 6A 10 91`
* `02 02 00 00 00 00 00 00` → CRC `0x40E9D2EF` → в проводе `EF D2 E9 40`
* стандартный вектор `"123456789"` → `0x0376E6E7`

### 2.2 Сборка команд
`QByteArray buildCommand(Type t)` — 14 байт: sync, version 2, type, seq = 0 (4 B LE), length = 0 (2 B LE), CRC (4 B LE). Никаких строк/переводов строк.

### 2.3 Потоочный парсер аудиокадров
`QByteArray m_acc` — аккумулятор; на каждый `readyRead()` дописываем `readAll()` и крутим автомат:

1. Найти `A5 5A` (при неудаче — отбросить байты, оставив возможный «хвост» sync).
2. Нужно ≥ 10 байт → проверить `version == 0x02`, `type == 0x10`, `length == 160`.
3. Нужно ≥ 174 байт → посчитать CRC, сравнить с принятым (LE).
4. Успех → выдать `AudioFrame{seq, payload[160], crc, rxTime}`; неуспех → сдвиг на 1 байт и ресинхронизация, `crcErrors++`.
5. Ограничение аккумулятора (например 64 КБ) + счётчик `resyncs`, чтобы мусор не рос бесконечно.

Требования: корректная работа при **любой** фрагментации (кадр приходит по 1 байту / по 3 кадра за одно чтение), устойчивое восстановление после порчи байта, отсутствие копирований в горячем пути (`remove(0, n)` батчами, `reserve`).

### 2.4 Нумерация и пропуски
* На START `expectedSeq = 0`; после каждого кадра `expectedSeq = (expectedSeq + 1) mod 2^32`.
* `delta = seq - expectedSeq` (по модулю 2^32): `delta > 0` → пропущено `delta` блоков (MCU отбросил при занятом UART DMA), `delta == 0` → норма, иначе — дубликат/устаревший кадр (логируем, в WAV не пишем).
* Политика пропусков (настройка, по умолчанию **вставка тишины**): дописывать `delta × 80` нулевых сэмплов, чтобы таймлайн WAV совпадал с реальным временем; в лог — явная строка `GAP n blocks`. Ограничение на разовую вставку (например ≤ 80 с) для защиты от мусорного seq.

## 3. Слой записи файлов

### 3.1 `WavWriter` (файл 2)
* Канонический RIFF/WAVE 44‑байтовый заголовок: `PCM(1)`, channels = 1, rate = 16000, byteRate = 32000, blockAlign = 2, bits = 16.
* Пишем **только payload** аудиокадров, байты уже little‑endian → ничего не переставляем.
  *Sizes (`RIFF size`, `data size`) патчим при закрытии; дополнительно **обновляем заголовок раз в ~1 с**, чтобы файл оставался играбельным при аварийном завершении.
* Ошибки записи (диск полон, нет прав) → сигнал `error()`, остановка сессии, корректное закрытие.
* Опционально `AiffWriter`: FORM/AIFF + COMM (80‑bit extended для 16000) + SSND, big‑endian сэмплы (байт‑свап).

### 3.2 `PacketLog` (файл 1)
Шапка: время старта, порт и его описание, параметры линии, версия протокола, формат payload, выбранные настройки.
Запись на каждый кадр (текстовый режим по умолчанию):

```
#00000123 t=+00:00:06.152 seq=123 exp=123 gap=0 len=160 crc_rx=0x1A2B3C4D crc_ok
A5 5A 02 10 7B 00 00 00 A0 00 <...полные 174 байта hex, 16 в строке...>
```

* Режимы (настройка): `full` (весь кадр hex, по умолчанию — «содержимое каждого пакета»), `payload`, `samples` (80 чисел int16), `header` (только поля).
* Опциональный CSV‑режим для машинной обработки.
* Хвост файла: время стопа, длительность, число кадров/сэмплов, счётчики (CRC‑ошибки, пропуски, ресинхронизации, ошибки UART).
* Буферизация: `QTextStream`/буфер + flush раз в ~200 кадров или 1 с; финальный flush + close на стопе.
* **Оценка объёма:** ~200 кадров/с × ~400 Б ≈ 80 КБ/с ≈ 4.8 МБ/мин ≈ 290 МБ/час — показать в UI и предупредить в настройках ( WAV при этом 1.9 МБ/мин).

### 3.3 `RecordSession`
* Создаёт `Data/` (путь по умолчанию рядом с exe, меняется в настройках), затем `Data/yyyy-MM-dd_HH-mm-ss` (при коллизии — суффикс `_01` или `.zzz`).
* Открывает оба файла **до** отправки START (чтобы не потерять первый кадр).
* Принимает `AudioFrame` → seq‑логика → WAV + лог + счётчики.
* `stats`: frames, samples, bytes, gapsTotal, crcErrors, resyncs, duplicates, elapsed, длительность WAV, текущий уровень (peak/RMS — опционально для индикатора).

## 4. Логика UART и конечный автомат

```
NO_PORT ──выбор порта──► READY ──Start──► OPENING ──успех──► STARTING
   ▲                       ▲                                   │ первый валидный кадр
   │                       │                                   ▼
   └──порт исчез/ошибка── ERROR ◄──ошибка── RECORDING ──Stop──► STOPPING ──► READY
```

* `OPENING`: `QSerialPort::open(ReadWrite)`, 921600, 8N1, `NoFlowControl`, `setReadBufferSize(1 << 20)`. Неудача (порт занят/нет прав) → сообщение, возврат в READY.
* `STARTING`: отправлен START, ждём первый кадр; таймаут ~2 с → предупреждение «нет аудио: проверьте питание/CKOUT/адаптер», но сессию не рвём (или рвём — настройка).
* `RECORDING`: разбор потока, запись файлов, обновление статистики.
* `STOPPING`: отправлен STOP; **drain‑окно 200–300 мс** — по спецификации уже начатый UART‑DMA кадр может дойти после STOP. Принимаем валидные кадры в этом окне, затем закрываем WAV/лог, закрываем порт, возвращаемся в READY.
* Обработка `errorOccurred(ResourceError)` (выдёргивание USB‑UART): немедленный graceful‑stop, файлы финализируются, ERROR + понятное сообщение.
* Все `write()` — неблокирующие, проверка возвращённого размера; **никаких `waitForReadyRead/waitForBytesWritten` в GUI‑потоке**.

### Потоки
MVP: всё в GUI‑потоке — нагрузка мизерная (~35 КБ/с, 200 кадров/с), файловые записи буферизованы, обновление UI по `QTimer` 5–10 Гц (не на каждый кадр!).
Архитектура сразу готова к переносу: `SerialLink + FrameParser + RecordSession` — один `QObject`‑фасад `RecorderWorker`, который при необходимости переезжает в `QThread` (создание `QSerialPort` внутри потока, общение с GUI только сигналами/слотами, статистика — снапшотами).

## 5. GUI

* Строка порта: ComboBox (`COM5 — USB-SERIAL CH340 (VID:PID)`), кнопка «Обновить», автообновление списка с сохранением выбора; при исчезновении выбранного порта — блокировка Start.
* Большая toggle‑кнопка: «Начать запись» / «Остановить запись» (иконки ● / ■, цвет).
* Панель статуса: состояние, время записи, кадров, пропусков (gap), CRC‑ошибок, ресинхронизаций, объём файлов, длительность WAV, путь к папке сессии + кнопка «Открыть папку».
* Опционально: индикатор уровня (peak/RMS из PCM), мини‑лог событий (не кадров!), поле выбора формата (WAV/AIFF) и режима лога.
* Настройки через `QSettings`: последний порт, каталог Data, политика пропусков, режим лога, drain‑таймаут.
* Закрытие окна во время записи → запрос подтверждения → корректный STOP + финализация файлов.
* Хоткеи: Space — старт/стоп, F5 — обновить порты.
